# Перелік скорочень — STT Handbook

**Версія:** 1.0
**Мова:** Українська з англійськими скороченнями
**Джерело:** CLAUDE.md, dataset/, міжнародні стандарти

Цей документ містить всі скорочення, що використовуються в посібнику. Скорочення наводяться в порядку виникнення в різних розділах.

---

## ⚠️ Правила виведення скорочень

1. **Першоджерело:** Скорочення беруться з англійської мови (міжнародний стандарт)
2. **Розшифровка:** При першому виведенні скорочення завжди розшифровується
3. **Послідовність:** Одне й те саме скорочення завжди має одне значення
4. **Контекст:** Якщо скорочення може мати кілька значень, повинен бути контекст

**Формат запису:**
```
СКОРОЧЕННЯ — Розшифровка (повна назва англійською) / Українська назва

Визначення / пояснення.

Джерело: посилання на dataset/ або стандарт
```

### LEAN — Lean Software Development

**Розшифровка:** Lean Software Development (або просто LEAN)
**Українська:** Бережлива розробка / Бережливість

**Визначення:**
Підхід до розробки ПЗ, заснований на концепції бережливого виробництва. LEAN прагне мінімізувати витрати та час розробки шляхом усунення всього, що не додає цінності продукту.

**Основні принципи LEAN:**
1. Визначення цінності (Identify Value)
2. Картування потоку цінності (Map Value Stream)
3. Створення потоку (Create Flow)
4. Встановлення pull (Establish Pull)
5. Прагнення до досконалості (Pursue Perfection)

**Ключові концепції:**
- **Muda (Мьюда)** — марнування, діяльність без цінності
- **Mura (Мура)** — нерівномірність процесу
- **Muri (Мурі)** — перевантаження людей/обладнання
- **Just-in-Time (JIT)** — розробка саме того, що потрібно, коли потрібно
- **Kanban** — система управління потоком робіт

**Контекст:**
- "LEAN-підхід" — мінімізація витрат та часу
- "LEAN-принципи" — видалення марнування
- "LEAN в тестуванні" — тестування лише критичних функцій

**Джерело:**
- `dataset/articles/qalight/parsed/osnovi/agile.md` — LEAN як фреймворк Agile
- `dataset/articles/QA_Bible/sdlc-i-stlc/agile.md` — детальна інформація про LEAN

### Kanban — (Система управління потоком)

**Розшифровка:** Kanban (японське: kan = карта, ban = дошка)
**Українська:** Канбан

**Визначення:**
Візуальна система управління потоком робіт, заснована на LEAN-принципах. Використовує дошку з картками та обмеженням WIP (Work In Progress).

**Структура Kanban:**
- **To Do** (Зробити)
- **In Progress** (Робиться) — з WIP Limit
- **Done** (Зроблено)

**Ключові поняття:**
- **WIP Limit** — максимум завдань одночасно в колонці
- **Lead Time** — час від початку до завершення роботи
- **Cycle Time** — час виконання одного завдання
- **Kanban Board** — фізична або цифрова дошка

**Переваги Kanban:**
- Видимість всіх робіт
- Скорочення часу виконання
- Гнучкість у приоритизації
- Запобігання перевантаженню

**Kanban vs Scrum:**
- Kanban: неперервний потік, змінна довжина цикла
- Scrum: ітеративні спринти, фіксована довжина

**Контекст:**
- "Kanban-дошка" — дошка управління проектом
- "Kanban-команда" — команда, що використовує Kanban
- "Kanban-ліміт" — обмеження на WIP

**Джерело:** `dataset/articles/qalight/parsed/osnovi/agile.md` — Kanban як фреймворк Agile

---

### WIP — Work In Progress

**Розшифровка:** Work In Progress
**Українська:** Робота, що виконується / Робота в процесі

**Визначення:**
Обмеження на кількість завдань, які можна мати одночасно в конкретній колонці дошки (часто у "In Progress"). WIP Limit — один із ключових інструментів LEAN та Kanban.

**Приклад:**
```
In Progress: WIP Limit = 5
Сьогодні в колонці 4 завдання — можна взяти нове
Сьогодні в колонці 5 завдань — нове потрібно чекати
```

**Переваги WIP Limit:**
- Запобігання перевантаженню команди
- Скорочення часу виконання (Lead Time)
- Визначення бар'єрів в процесі
- Поліпшення якості роботи

**Контекст:** "WIP Limit на спринт", "WIP Limit 3 завдання на розробника"

**Джерело:** LEAN та Kanban методологія

### JIT — Just-In-Time

**Розшифровка:** Just-In-Time
**Українська:** Саме в час / Точно в час

**Визначення:**
Принцип розробки, при якому розробляється саме той функціонал, який потрібен саме тоді, коли він потрібен. Заснований на LEAN-виробництві, де запаси мінімізуються.

**Контекст JIT:**
- "JIT-розробка" — розробка функцій по мірі потреби
- "JIT-тестування" — тестування паралельно з розробкою
- "JIT-доставка" — спринти, доставка готового функціоналу

**Переваги JIT:**
- Мінімізація витрат на сховищах/доставці
- Гнучкість у змінах вимог
- Скорочення часу розробки

**Джерело:** LEAN методологія, запозичено з виробництва Toyota

## Правила стилю для скорочень у посібнику

1. **Першоджерело:** Скорочення наводяться у англійській мові (міжнародний стандарт)
2. **Розшифровка:** При першому виведенні скорочення завжди розшифровується повністю
3. **Послідовність:** Один оформ скорочення завжди має одне значення в посібнику
4. **Конвенція:**
   - Скорочення цілком літерами: JIRA, QA, API
   - Скорочення в нижньому регістрі через дефіс для звичайних слів: REST, Agile
