# QA Knowledge Base Dataset (By-Source Branch)

Цей репозиторій містить датасет матеріалів для QA-інженерів, а також ETL-пайплайн для його наповнення.

## Структура датасету

У цій гілці реалізовано поділ за джерелами. Дані зберігаються у точній відповідності до ієрархії їхнього першоджерела (наприклад, навігаційне меню сайту). Цей підхід дозволяє зберегти контекст та задум авторів матеріалу.
*Альтернативна гілка `dataset/by-topic` містить ті ж дані, але перегруповані за предметними категоріями (наприклад, ISTQB).*

Поточна структура:
- `data/` (або папки з назвами доменів, напр. `qalight.ua/`)
  - `automation-of-testing/`
  - `databases/`
  - ...та інші оригінальні розділи сайту.

## Інструмент збору (`tools/pipeline.py`)

Для автоматизації збору використовується ETL-скрипт, який працює у три етапи:
1. **Discover:** Асинхронний парсинг навігаційного меню сайту (багатоступеневі списки) для формування структури шляхів типу `domain/category/subcategory` та збереження у `raw_discovery.jsonl`.
2. **Classify:** LLM-аналіз (Gemini API) через `google-genai` та `pydantic`. Модель працює виключно як фільтр (`keep: True/False`), відкидаючи нерелевантні загальні ІТ-статті. Використовується алгоритм ковзного вікна для захисту від блокувань API (ліміт 5 запитів/хв) при пакетній обробці по 30 статей.
3. **Download:** Асинхронне завантаження (`httpx`), очищення HTML від реклами/навігації (`BeautifulSoup4`) та збереження у Markdown (`markdownify`) зі збереженням згенерованої структури папок.

### Залежності та запуск
Для етапу класифікації потрібна змінна середовища:
`export GEMINI_API_KEY="ваш_ключ"`

Запуск пайплайну:
```bash
python tools/pipeline.py -h
```

## Наступні кроки
- Парсинг PDF (PyMuPDF) та DOCX (python-docx). Дані з цих джерел будуть розміщені в окремих папках з іменами авторів або джерел.
