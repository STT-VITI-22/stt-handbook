# QA Dataset ETL Pipeline

Цей репозиторій містить ETL-пайплайн для збору, класифікації та форматування статей з QA-інженерії у структурований набір даних. Класифікація виконується через Gemini API з використанням структурованих відповідей Pydantic для розподілу контенту за доменами ISTQB Foundation Level.

## Архітектура

Управління пайплайном здійснюється через `tools/main.py`. Процес складається з трьох етапів:

### 1. Discovery (`etl/discovery.py`)
Завантажує цільові URL-адреси з `sources.yaml` та витягує посилання на статті за допомогою асинхронних HTTP-запитів (`httpx`) та CSS-селекторів (`BeautifulSoup`). Зберігає результат у `raw_discovery.jsonl`.

### 2. Classification (`etl/ai.py`)
Оцінює знайдені статті та призначає їм категорії на основі силабусу ISTQB.
- **Аналіз контенту**: Перед відправкою запиту до LLM завантажує перші 500 символів тексту кожної статті. Це зменшує кількість помилок класифікації через неоднозначні заголовки.
- **Категоризація**: Використовує структуровану відповідь Gemini для призначення домену ISTQB (наприклад, `test_levels`, `defect_management`). Нерелевантний контент позначається для видалення (`keep: False`).
- **Маршрутизація курсів**: Статті, URL яких містить `/kursy/`, примусово отримують категорію `courses` на рівні коду, оминаючи класифікацію LLM.
Зберігає результат у `manifest.jsonl`.

### 3. Download & Formatting (`etl/downloader.py`)
Завантажує та конвертує затверджені HTML-статті у Markdown.
- **Ідемпотентність**: Цільова директорія `data/` повністю очищається перед виконанням для запобігання збереженню застарілих файлів.
- **Конвертація Markdown**: Використовує `markdownify`. Вбудовані зображення всередині заголовків зберігаються завдяки параметру `keep_inline_images_in`. Екранує буквальні HTML-теги (наприклад, `<head>`) у блоки коду для уникнення проблем із рендерингом Markdown.

## Використання

Встановіть необхідну змінну середовища:
```bash
export GEMINI_API_KEY="your_api_key_here"
```

Запуск повного циклу:
```bash
uv run python tools/main.py run_all --strategy topic
```

### Стратегії
- `--strategy topic` (за замовчуванням): Використовує домени ISTQB, призначені LLM, для структури вихідних директорій.
- `--strategy source`: Використовує оригінальні шляхи з вихідного веб-сайту. URL-адреси, що містять `/kursy/`, все одно ізолюються в директорію `courses/`.

## Конфігурація
Джерела та параметри парсингу визначаються у файлі `tools/sources.yaml`.
