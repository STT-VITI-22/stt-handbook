# Метрики

- це формули, що вираховують певні числа і результати. Ці результати показують успішність роботи, проекту, продукту. Метрики називають “мірою зворотнього зв’язку” і збирають для розвитку проекту.

# Кількість бензину на певну відстань

5,5 л (розхід) / 100км * к-ть пройдених км = необхідна к-ть бензину

## Base (absolute) metrics

* Загальна к-ть тест кейсів
* К-ть тест кейсів, що пройшли
* К-ть тест кейсів, що впали
* К-ть заблоканих тест кейсів
* К-ть знайдених багів
* К-ть критичних багів
* К-ть відхилених багів
* К-ть багів, знайдених після релізу

## Тестове покриття = к-ть тестів / к-ть вимог

* Якщо результат ~ 1, то покриття нормальне.
* Якщо > 1, то покриття хороше.
* Якщо < 1, то покриття погане, і треба терміново дописувати тести.

% пройдених тестів = к-ть тестів, що пройшли / загальна к-ть тестів * 100%

Чим ближче % до 100, тим краще

**Defect Leakage** = к-ть багів, знайдена під час UAT / к-ть багів, знайдена під час тестування * 100%

Густина дефектів в модулі = к-ть багів в модулі / загальна к-ть багів * 100%

Чим менше число, тим безпечніше модуль і менше тестування там потрібно.

**Частина повторно відкритих багів** = к-ть повторно відкритих багів / к-ть всіх багів

Чим менше число, тим якісніше виправляються дефекти.

Швидкість роботи команди = к-ть SP за n спринтів / n

Capacity = (к-ть годин за день * к-ть робочих днів) - к-ть годин у відпустці

Velocity = к-ть годин, витрачених людиною на спринт

Продуктивність людини = Capacity - Velocity

# Типи метрик

* **Process** — метрики, пов'язані з ЖЦ розробки ПЗ
* **Product** — метрики якості програми, що розробляється
* **Project** — метрики успішності команди, проекту і т.п.
