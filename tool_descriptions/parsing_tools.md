# Парсинг та обробка даних: Документація інструментів

Цей документ описує стек технологій та архітектуру скриптів для збору датасетів (веб-сторінки, PDF, DOCX) та їх конвертації у Markdown для подальшої машинної обробки.

## 1. Web-парсер (HTML -> Markdown)

Інструмент призначений для асинхронного завантаження веб-сторінок, точкової екстракції контенту та локального збереження медіафайлів.

### Технологічний стек
- **Менеджер залежностей:** `uv` (швидке розгортання оточення з фіксацією версій).
- **Мережевий шар:** `httpx` (асинхронний клієнт для паралельного завантаження ресурсів).
- **Обробка HTML:** `BeautifulSoup4` + `lxml` (C-базований парсер для ефективного розбору DOM-дерева).
- **Трансформація:** `markdownify` (конвертація очищеного HTML у Markdown).
- **Неймінг файлів:** `deep-translator` + `python-slugify` (автоматичний переклад заголовків для генерації англомовних, машиночитних URI).

### Алгоритм роботи
1. **Extract:** Запит до URL. Пошук основного контейнера статті за допомогою точкових CSS-селекторів.
2. **Clean:** Видалення з DOM-дерева скриптів, стилів, а також вкладених навігаційних елементів (сайдбарів, футерів), що знаходяться всередині контентного блоку.
3. **Asset Management:** Завантаження зображень (`<img>`) локально у папку `assets/`. Заміна абсолютних URL на відносні шляхи в HTML.
4. **Transform:** Конвертація чистого DOM-вузла у Markdown.

## 2. Обробка PDF (Заплановано)

- **PyMuPDF (fitz) / PyMuPDF4LLM:** C-базований рушій для швидкої екстракції тексту, збереження координатної структури блоків та витягування векторних/растрових зображень.

---

## 3. Обробка DOCX (Заплановано)

- **python-docx:** Пряма робота з XML-архівом документа для отримання параграфів, стилів, таблиць та оригіналів зображень без рендерингу.
- **pypandoc:** Системна утиліта для стандартизованої конвертації DOCX у Markdown.

## 4. Структура датасету

```text
dataset/
├── tool_descriptions/        # Технічна документація
├── tools/                    # Скрипти та віртуальне оточення (.venv)
└── {domain}/                 # Коренева папка ресурсу (напр., qalight)
    └── {category}/           # Категорія
        └── {subcategory}/    # Підкатегорія
            ├── assets/       # Локальні медіафайли
            │   └── img.png
            └── article.md    # Очищений Markdown-файл
```
