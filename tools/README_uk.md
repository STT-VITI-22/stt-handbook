# QA Dataset ETL Pipeline

Пайплайн для збору, класифікації та форматування статей з QA у структурований набір даних.

## Структура пайплайну

Процес керується через `tools/main.py` і складається з трьох етапів:

### 1. Discovery (`etl/discovery.py`)
Збирає URL-адреси статей на основі налаштувань у `tools/sources.yaml`. Використовує асинхронні запити (`httpx`) та парсинг DOM (`BeautifulSoup`) для отримання посилань та структури оригінального меню сайту.

### 2. Classification (`etl/ai.py`)
Класифікує зібрані статті за категоріями ISTQB Foundation Level за допомогою Gemini API.
- **Отримання контенту:** Завантажує перші 500 символів кожної статті для передачі контексту в LLM. Це допомагає моделі точніше визначати тематику порівняно з аналізом лише за заголовком.
- **Категоризація:** Використовує Structured Outputs (Pydantic) для валідації вибраної категорії зі списку доменів ISTQB. Статті, які модель визначає як нерелевантні, відкидаються (`keep: False`).
- **Маршрутизація курсів:** Якщо URL містить `/kursy/`, стаття автоматично отримує категорію `courses` незалежно від відповіді LLM.
- **Лімітування запитів:** Вбудований алгоритм обмежує частоту запитів до API, щоб уникнути помилок 429 (Too Many Requests).

### 3. Extraction & Formatting (`etl/downloader.py`)
Завантажує HTML-вміст статей і конвертує його в Markdown.
- **Очищення:** Цільова директорія для збереження даних повністю видаляється та створюється наново перед початком завантаження.
- **Конвертація Markdown:** Використовує бібліотеку `markdownify`. Для збереження зображень (тегів `<img>`), що знаходяться всередині заголовків або параграфів, застосовується параметр `keep_inline_images_in`. Літеральні HTML-теги в тексті (наприклад, `<head>`) екрануються зворотними апострофами.

## Використання

Налаштуйте змінну середовища з API ключем:
```bash
export GEMINI_API_KEY="your_api_key_here"
```

Запустіть пайплайн:
```bash
uv run python tools/main.py run_all --strategy topic
```

### Стратегії збереження (`--strategy`)
- `topic` (за замовчуванням): Розподіляє файли по директоріях відповідно до категорій ISTQB, визначених на етапі класифікації.
- `source`: Зберігає файли у директоріях, що повторюють структуру оригінального сайту.
Усі матеріали з категорії `courses` зберігаються в окремій однойменній папці незалежно від обраної стратегії.
