# Парсери Документації та База знань QA

Інструментарій для конвертації технічної документації, книг, презентацій та веб-ресурсів у Markdown формат.

## Архітектура

Проєкт має модульну структуру, розділену на парсери локальних файлів (PDF, PPTX) та веб-ресурсів.

### 1. Парсер Документів (`tools/doc_parser/`)
Використовує комбінацію `PyMuPDF` для екстракції контенту та `Gemini API` для форматування тексту.

- **Режим презентацій (`--type pptx`)**: Витягує текст і зображення зі слайдів. Видаляє дубльовані зображення (водяні знаки) шляхом порівняння їх MD5-хешів та площі. Слайди групуються за заголовками (`SlideChunker`), щоб уникнути розриву речень.
  - *Недоліки/Корявості*: Визначення заголовків базується на розмірі шрифту. Ця евристика часто помиляється, якщо на слайді є більший текст (наприклад, номер схеми) або якщо всі тексти однакового розміру.

- **Режим PDF (`--type pdf`)**: Призначений для технічних книг. Використовує `get_text("dict")` для вилучення відрендерених блоків. Має fallback на режим OCR, якщо сирий текст відсутній (сканована книга). 
  - *Недоліки/Корявості*: Спроба впровадити семантичний чанкінг провалилася. Щоб уникнути лімітів API, введено жорстке обмеження у 5 сторінок на запит, що повністю повертає проблему розриву речень на стиках чанків. Блоковий аналіз `dict` часто порушує фізичний порядок читання (особливо у двоколонковій верстці) та губить не-растрові діаграми. Розробку нового парсера призупинено, для книг тимчасово використовується `legacy/gemini_pdf_parser.py`.

**Використання:**
```bash
# Парсинг презентації
uv run python tools/doc_parser/parse_docs.py "path/to/lecture.pdf" --type pptx_doc

# Парсинг книги
uv run python tools/doc_parser/parse_docs.py "path/to/book.pdf" --type pdf
```

### 2. Веб-скрейпери (`tools/web_scrapers/`)
Парсери для веб-ресурсів (запускаються через `tools/main.py <назва>`):
- **`gitbook`**: Парсер для QA Bible. Замість HTML-скрейпінгу завантажує файл `llms.txt` для отримання карти сайту та системні `.md` ендпоінти для прямого отримання сирого Markdown. Шляхи до зображень конвертуються в абсолютні.
- **`qalight`**: Парсер бази знань QALight. Аналізує HTML через BeautifulSoup.
- **`dou`**: Парсер форуму dou.ua. Видаляє коментарі та UI.

### 3. Застарілі скрипти (`tools/legacy/`)
Містить старі монолітні парсери (напр., `gemini_pdf_parser.py`, `gemini_pptx_parser.py`), які використовують посторінкову обробку.

## Структура збереження даних

- `dataset/pptx_doc/` — Форматовані технічні презентації.
- `dataset/books_pdf/` — Конвертована ІТ-література (використовує legacy-парсер).
- `dataset/QA_Bible/` — База знань QA Bible (GitBook).
- `dataset/qalight/`, `dataset/dou/` — Веб-статті.
